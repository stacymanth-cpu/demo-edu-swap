1. Project Overview

EduSwap is a skill exchange platform where university students trade knowledge instead of money. A student who can teach Mathematics but wants to learn Programming is matched with someone who can teach Programming but wants to learn Mathematics. The platform facilitates scheduling, communication, progress tracking, and a credit-based economy.

Problem Statement

Many students cannot afford private tutoring or supplementary learning resources. Meanwhile, fellow students possess valuable skills and knowledge they could share. There is no structured platform that connects these complementary needs within and across university communities.

Solution

EduSwap provides a dual-platform (Android + Web) solution that:

  • Automatically matches users with complementary skill sets
  • Enables session scheduling with Microsoft Teams integration
  • Tracks learning progress through a credit system
  • Facilitates real-time communication between matched users
  • Supports multiple universities with cross-institution matching
  • Provides community feedback through comments and ratings

Key Objectives

2. System Architecture

Both the Android and Web applications share a single Firebase backend, ensuring data consistency across platforms.

Why Firebase? Zero server management, built-in authentication, real-time database listeners, generous free tier, and automatic scaling — ideal for a student project that needs to be demo-ready quickly.

9. Matching Algorithm

FUNCTION findMatches(currentUser):
  candidates = []

  // Step 1: Find users whose skillsTeach intersects currentUser.skillsLearn
  potentialTeachers = query users WHERE skillsTeach array-contains-any currentUser.skillsLearn

  // Step 2: Filter for reciprocal match
  FOR each teacher IN potentialTeachers:
    IF teacher.skillsLearn intersects currentUser.skillsTeach:
      matchScore = calculateScore(currentUser, teacher)
      candidates.add({user: teacher, score: matchScore})

  // Step 3: Sort by score descending
  RETURN candidates.sortByDescending(score)

FUNCTION calculateScore(userA, userB):
  score = 0
  score += countOverlap(userA.skillsTeach, userB.skillsLearn) * 30   // Skill relevance
  score += countOverlap(userB.skillsTeach, userA.skillsLearn) * 30   // Reciprocal relevance
  IF userA.university == userB.university: score += 20                // Same university bonus
  score += userB.rating * 4                                           // Rating bonus (max 20)
  RETURN score

10. Credit System

ON session_completed(session):
  // Teacher earns credits
  teacher.credits += session.creditsExchanged
  log CreditTransaction(userId=teacher, amount=+10, type="earned_teaching")

  // Learner spends credits
  learner.credits -= session.creditsExchanged
  log CreditTransaction(userId=learner, amount=-10, type="spent_learning")

ON user_registered(user):
  user.credits = 50
  log CreditTransaction(userId=user, amount=+50, type="welcome_bonus")

ON review_posted(review):
  IF review.rating == 5:
    teacher.credits += 5
    log CreditTransaction(userId=teacher, amount=+5, type="five_star_bonus")

11. Microsoft Teams Integration

How It Works

  1. When scheduling a session, the teacher creates a Teams meeting (via Teams app or Outlook)
  2. They paste the meeting URL into EduSwap's session form
  3. The link is stored in Firestore with the session
  4. Both users see a "Join on Teams" button on the session card

Android Implementation

fun openTeamsLink(context: Context, teamsUrl: String) {
    val intent = Intent(Intent.ACTION_VIEW, Uri.parse(teamsUrl))
    try {
        context.startActivity(intent)
    } catch (e: ActivityNotFoundException) {
        // Fallback: open in browser
        val browserIntent = Intent(Intent.ACTION_VIEW, Uri.parse(teamsUrl))
        context.startActivity(browserIntent)
    }
}

Web Implementation

function openTeamsLink(teamsUrl: string): void {
  window.open(teamsUrl, '_blank');
}
URL Format: Teams meeting links follow the pattern:
https://teams.microsoft.com/l/meetup-join/...
The app validates this format before saving.

15. Deployment Strategy

📱 Android

  1. Generate signed APK via Android Studio
  2. Test on physical device
  3. Optional: publish to Google Play (requires developer account, $25 fee)
  4. For demo: install APK directly on test device

🌐 Web

  1. Build: npm run build
  2. Deploy: firebase deploy
  3. Free SSL + CDN via Firebase Hosting
  4. Custom domain available (optional)
Before Deployment:
  • Set Firestore security rules (restrict read/write to authenticated users)
  • Enable only required Firebase Auth providers
  • Test all features with production Firebase project
